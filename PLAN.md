# План реализации — чат через GREEN-API (Telegram)

Тестовое задание: UI для отправки/получения текстовых сообщений через GREEN-API
(https://green-api.com/), прототип интерфейса — https://web.max.ru/. Фактически
канал в GREEN-API подключён как Telegram (MAX был недоступен при создании инстанса).

## Стек

- Vite + React 19 + TypeScript
- antd — UI-кит
- axios — HTTP-клиент
- zustand (+ `persist`) — состояние авторизации с сохранением в localStorage
- Архитектура: Feature-Sliced Design (`app → pages → features → entities → shared`)

## Структура проекта (FSD)

```
src/
├── app/            # композиция приложения, роутинг по состоянию авторизации
├── pages/
│   └── login/      # страница логина
├── features/
│   └── auth/       # вход по idInstance/apiTokenInstance (model: zustand-store, ui: форма)
├── entities/
│   ├── instance/    # getSettings — проверка instance
│   └── message/     # sendMessage — отправка сообщения
└── shared/
    └── api/         # instanceUrl(), общий тип GreenApiCredentials
```

Правила: импорты только вниз по слоям, каждый слайс отдаёт публичный API через `index.ts`,
сущности не зависят друг от друга напрямую.

## Открытые вопросы / риски

- Формат `chatId` для Telegram: проверено на реальном инстансе (этап 5) — GREEN-API **не**
  резолвит получателя по номеру телефона для Telegram-канала (в отличие от WhatsApp, где номер
  и есть `chatId`). Реально работает только числовой `chatId` вида `281746716`, который берётся
  из личного кабинета GREEN-API (история чатов / входящие). Форма «Новый чат» всё равно принимает
  номер телефона (единый UI под разные каналы), но для Telegram такой чат может не доставлять
  сообщения — нужен настоящий `chatId`.
- CORS к `api.green-api.com` из браузера — проверено, работает «из коробки».
